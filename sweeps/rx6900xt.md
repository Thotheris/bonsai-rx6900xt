# Radeon RX 6900 XT (gfx1030), Windows HIP

This staging row is for one 16 GiB RX 6900 XT running the pinned PrismML fork plus `kernel/patches/0001-rdna2-ptq1-hip-mmvq.patch`. Build with `kernel/build-staging.cmd` to produce your own `ggml-hip.dll`; do not treat another checkout's binary hash or speed as your result. The two current Bonsai 2 models are PTQ1_0 (`53107f530aa52eb00912263ab1ee29bd199261c87cd7b4ad4ca1318c1fe33ee3`) and PQ2_0 (`3907dc1658db1f78a9826bf8d5bcb8dc65db0d466388937af57f2294fae62ec1`). The older PQ2 model (`e4781999...`) is not the Bonsai 2 PQ2 release.

## Existing PTQ1 evidence (earlier local build)

A prior two-row source-equivalent DLL, SHA-256 `b077258e2656a50a0000ab61fe32b4c192033e8159e9f412242466aa5b59266a`, passed 78/78 PTQ1 backend operations and strict frozen-greedy token/UTF-8 identity in three 128-token prompts with MTP on/off. Six reversed-order depth-32768 MTP-on pairs measured a median **+26.932%** over the frozen fork; six MTP-off `llama-bench` pairs measured **+22.231%**. The benchmark was desktop-active with unverified GPU residency. Raw receipts were retained locally but excluded from the staging repository because they contain machine-specific paths and GPU process inventories. These deltas do not automatically transfer to a fresh DLL with a different hash.

## New Bonsai 2 PQ2 model

The Bonsai 2 PQ2_0 model is 7,206,168,928 bytes and has SHA-256 `3907dc1658db1f78a9826bf8d5bcb8dc65db0d466388937af57f2294fae62ec1`. No historical PQ2 speed curve in this repository applies to that file; measure it afresh before publishing a throughput number. The former model was 7,165,121,600 bytes and belongs to an older Bonsai release. PQ2 is not changed by the PTQ1-specific HIP patch.

The fresh source-built DLL (`dde7a42df68cdbeeb23654d4cc02e9fb2e45e56b8634904c98aebc0b768cb648`)
passed 49/49 supported PQ2 backend operations; 33 F16-input cases were
unsupported by both devices, with zero failures. Its grafted Bonsai 2 PQ2
file passed three 128-token greedy MTP off/on identity prompts. At depth
32768 within context 65536, one exploratory 128-token sample was
34.48 tok/s with MTP off and 32.69 tok/s with MTP on. Both samples are
valid rows, but each arm has **one** repetition, so the protocol marks both
aggregate headlines invalid; GPU residency was unverified. This is not
evidence of a PQ2 MTP speedup or a production throughput claim.

The previous 262144-token fit probe was **inconclusive**, not evidence of fit or a memory spill. The older 204800-token fill curve was `residency-unverified`; neither is a guaranteed resident configuration for the new PQ2 file. Start at context 32768 and record per-process memory and actual model/DLL hashes. Run one GPU model or benchmark process at a time. For a new card row use `CONTRIBUTING.md` and include three valid same-session repetitions, raw min/max (in your own sanitized summary), and the exact protocol.
